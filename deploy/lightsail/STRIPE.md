# Credit-card donations — Stripe test mode

The donation form is `/donate-money/new` (sign-in required). It offers $10, $25,
$50, $100, $500 or a custom USD amount from $1 to $10,000. All verified users can
give, consistent with equipment donation access. Donors see their own history at
`/donate-money`. No card data is entered into or stored by this application.

This implementation deliberately accepts **only test keys** and displays test
mode throughout. It cannot collect real money. Missing configuration disables
checkout without affecting the rest of the application.

## Configure on Lightsail

1. Create/sign in to the organization's Stripe account and open its test sandbox.
2. In Developers / Workbench, create a webhook destination for:
   `https://test.mobilityexchange.org/webhooks/stripe`
   Subscribe to `checkout.session.completed`, `checkout.session.expired`, and
   `checkout.session.async_payment_succeeded`. Use the account's snapshot events.
3. Retrieve the sandbox secret API key (`sk_test_...`) and this destination's
   signing secret (`whsec_...`). Do not paste them into chat or commit them to Git.
4. In the server SSH terminal run:

   ```sh
   cd /home/ubuntu/mobility-exchange/deploy/lightsail
   python3 configure-stripe.py
   sudo docker compose up -d --force-recreate web worker
   ```

   The script prompts privately and updates `.env` with file permissions 600.
   A publishable key is not required for hosted Checkout.

When deploying the feature, build the image, then migrate before recreating web:

```sh
sudo docker compose build web
sudo docker compose run --rm web bin/rails db:migrate
sudo docker compose up -d web worker
```

## Verify in the Stripe sandbox

Sign in as a verified test user, choose an amount, and continue to Checkout.
Use Stripe's test card `4242 4242 4242 4242`, a future expiry and any three-digit
CVC. Never use a real card in test mode. Verify the amount, successful redirect,
Paid status, and the webhook's successful delivery. Also test a decline with
`4000 0000 0000 0002`, cancel/back navigation, custom amount validation and webhook
resends. A decline stays pending until checkout succeeds or expires; it is never
counted as paid. These are one-time donations, not recurring subscriptions.

The signed webhook and a server-side status retrieval both validate the stored
session ID, donation reference, amount, currency, test mode and payment status.
Repeat notifications cannot repeat the paid transition. POST retries reuse the
same local record and Stripe idempotency key. External API requests never run
inside retryable database transactions. The return URL alone is not proof of
payment. Stripe API errors render inline and do not display credential details.

No email or charitable tax receipt is generated by this feature. Refunds and
disputes are managed in Stripe; the local history records original checkout
payment status and does not yet reconcile refunds/disputes. Going live requires
a separate implementation/configuration change and verification of the live
account, webhook and payment lifecycle.
